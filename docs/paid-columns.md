# 付费专栏与微信支付

## 作者工作流

1. 在管理端“小册”填写名称、简介和人民币价格；永久链接自动生成，改名不改变已有链接。
2. 在文章发布设置中像选择分类一样选择所属专栏。关闭“付费阅读”时免费开放全文；开启后未订阅读者只能试看前 30%，不需要单独编写试看正文。
3. 保存并发布。旧文章默认公开，不会因迁移自动进入专栏。

专栏是统一订阅的文章分组，全部已发布篇章的标题与公开摘要形成目录，任何读者都能查看。付费全文仍保存为服务端文章文档与 HTML。未购读者请求文章详情时，Axum 按净化后 HTML 的可见文字数量向下取整截取前 30%，重新闭合标签；不足四字的正文不输出试看文字。截取范围不接受客户端参数，旧版手填试看也不会替代自动裁剪。完整 HTML 和原始 Markdown 不进入未购读者的公开 JSON 或 SSR。管理员编辑接口继续要求管理员会话与 CSRF。搜索索引对付费篇章只写标题、公开摘要和同规则生成的试看内容；部署新版本前执行 `--reindex`。

### 小册与分类的边界

界面统一称为“小册”，现有 `/columns` 路由和 API 字段保持稳定。分类和标签负责主题归档；小册负责成组章节、独立简介、定价和订阅权益，因此单独管理。当前小册尚未实现封面字段。

首页在分类下方展示独立小册板块，最多展示六本并链接到完整目录。归属小册的免费和付费章节均不进入首页写作、普通归档或 RSS；仓储在数据库分页和计数前统一过滤小册归属。章节仍可通过小册目录和原文章链接阅读，也可按主题分类、标签或搜索发现。

文章自己的完整二、三级标题大纲也公开展示；API 单独返回标题文字和可读状态，不返回隐藏段落、标题属性或链接。未订阅者点击锁定的小节进入订阅入口，试看范围内的小节可正常跳转。

## 读者与支付

读者使用独立的用户名和密码注册。读者 Cookie 为 HttpOnly、SameSite=Lax，并在 HTTPS 部署时设置 Secure。微信 Native 扫码订单由已登录读者发起，金额取数据库中的当前专栏价格；订单保存价格快照。前端轮询仅显示服务端订单状态，不能自行授予订阅。

在 `.env` 配置全部 `WECHAT_PAY_*` 变量，并确保 HTTPS 公网回调能到达 Axum 的 `/api/v1/wechat/notify`。商户私钥使用 PKCS#8 PEM；平台公钥 PEM 与 `WECHAT_PAY_PLATFORM_SERIAL` 必须匹配微信支付当前公钥 ID 或平台证书序列号。商户号、AppID、API v3 密钥以及回调 URL 从微信商户平台取得。项目没有商户资料时仍可创建专栏、注册读者和展示试看，但下单返回 `503 payment_unavailable`。

回调会核验微信 RSA 签名、平台公钥标识和时间窗口，再用 API v3 密钥解密；随后逐项比对商户号、AppID、商户订单号、实付金额和支付状态。订单与订阅在同一 PostgreSQL 事务内更新，重复通知按流水号幂等处理。没有经过验证的成功回调，数据库不会建立阅读权限。

## 部署边界

- 公开 API、SSR 和 CDN 不得缓存带读者 Cookie 的正文响应；付费详情返回 `Cache-Control: private, no-store` 和 `Vary: Cookie`。前端服务端请求按当前请求转发 Cookie。
- `/media/{public_id}` 的公开素材仍可直接访问，因此付费章节中的图片若作为公开素材上传，图片本身不是受保护内容。不要把需要保密的原图放进公开素材库。
- 读者付款后若微信通知无法到达，订单不会开通订阅；部署时必须监控通知端点并保证其公网可达。
