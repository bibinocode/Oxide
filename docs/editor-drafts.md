# 编辑器自动保存与刷新恢复

## 两层保护

编辑正文、标题、摘要、slug、封面和分类标签都会触发本地恢复草稿，停止输入 200 ms 后写入。切到后台、刷新或离开时同步补写，不依赖网络请求一定赶在页面关闭前完成。恢复键按管理员名称与文章 UUID 隔离；新文章有独立槽位，自动创建后记录服务端 UUID，刷新不会重复创建。

草稿停止输入 1500 ms 后通过现有管理员 API 自动保存到服务器，创建或更新的文章保持 draft，不会自动发布。调用串行化，保存期间继续输入的内容会再次触发保存；成功状态只对应已完成的快照。正文、封面和分类标签全部成功才显示完整保存成功。

已发布文章的编辑只自动写本地恢复草稿，不自动修改公开正文；用户点击保存修改后才更新服务端内容。API 的 draft_only 保证即使另一窗口在期间发布文章，自动保存也会被拒绝。

## 冲突与故障

保存时携带 expected_updated_at，服务端使用 SeaORM 行锁与事务检查版本。版本不一致返回 409，不静默覆盖其他标签页或外部同步的更新。刷新恢复时若本地记录的版本不同于服务器，保留本地内容，显示冲突提示并暂停自动保存，用户核对后可明确手动保存。

网络失败会暂停自动保存，保留本地草稿并显示失败原因，不无限循环重试或冒充成功。用户点击保存重试。首次加载未完成时禁用正文与标题编辑，防止迟到的服务器响应覆盖新输入。

本地缓存写入失败或容量超限会明确提示；不安全的离开仍需确认。单个恢复记录限制 2,000,000 个 JavaScript 字符，不保存 AI 会话、图片附件、密钥或 Cookie。浏览器自身总存储配额仍可能更低。

## 边界

本地恢复草稿属于当前浏览器和站点，不是跨设备同步，浏览器清理数据会丢失尚未提交的恢复记录。本地缓存不加密，不应在共享浏览器账户中编辑私密文章；需要长期保存的内容应确认服务器保存成功。

已完成保存的既有文章会清理其恢复记录；删除文章时清理对应本地记录。手动保存新文章并切换到 UUID 编辑页时，把保存期间仍继续编辑的内容转移到新的恢复槽位。
