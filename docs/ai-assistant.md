# AI 写作与 Agent 工作流设计

本文件记录已落地能力和后续实施边界。目前已有 Markdown 写作、同源渲染预览、发布面板、封面素材、图像生成与 OSS 入库、独立 Agent 模型注册、加密密钥和任务绑定。审核工作流仍待实现。

## 编辑器边界

当前第一阶段写作助手已实现：CodeMirror 空行按空格打开自由写作输入，选中文字可解释、优化或续写；Rig 流式生成经 SSE 逐段送到编辑器原位 widget，优化时原文选区保留并标记删除，新增候选在旁显示 Diff。候选可编辑，收到完成事件后管理员确认，才以一次可撤销事务写入。解释结果只供阅读。请求期间正文变化会阻止旧候选采纳。FIM 补全仍按下述契约继续建设。

使用成熟的 CodeMirror 6（`@uiw/react-codemirror`）编辑 Markdown 原文。AI 能力不绑定 Tiptap：编辑器适配层负责获取选区、前缀、后缀、文档版本，及执行可撤销的插入/替换事务。后续即使增加富文本模式，也共用 AI 业务接口。

- FIM 补全：传递 cursor 前缀和后缀；仅对声明支持 FIM 的模型启用，短时防抖，光标移动或新输入取消请求，Tab 接受，Esc 拒绝。
- 续写、改写：SSE 流式返回候选文本，先预览差异，接受后作为一次编辑事务，支持撤销。请求绑定文档版本，不能覆盖用户后来输入的内容。
- AI 摘要：位于发布面板；生成候选摘要，管理员可修改后采用。
- AI 主图与配图：结果进入现有 OSS 素材库，返回素材 UUID；发布面板选择主图，正文配图插入 Markdown 图片语法。
- AI 流程图：返回 Mermaid 文本并以受限方式渲染，不把模型输出当作可执行 JS/MDX；最终正文保留原始图定义。

## 模型与设置

管理员 Agent 设置使用独立 API，不把模型密钥放入公开 `/api/v1/site`。当前支持注册 `openai_compatible` 和 `jimeng` 协议配置，并绑定写作、摘要、生图和对话任务；调用适配器需按协议分别实现与测试。

| 配置 | 内容 |
| --- | --- |
| 提供商 | OpenAI、DeepSeek 或兼容适配器；管理员维护名称与 API 基础地址 |
| 凭据 | 服务端加密保存或密钥引用；读取仅返回掩码和是否已设置 |
| 模型 ID | 可编辑字符串，例如用户指定的 `deepseek4pro` 或实际可用的 OpenAI 模型 ID；通过连接测试确认可用性，不硬编码未验证的别名 |
| 能力 | chat / FIM / image / structured-output 分别记录，不能假定一个模型具备全部能力 |
| 任务绑定 | 补全、续写、摘要、配图、流程图和审核分别选择模型 |
| 运行限制 | 超时、最大输出、并发、费用预算、重试和取消 |
| 提示模板 | 各写作任务、封面风格模板独立可维护 |

服务端领域层定义 provider trait 与任务模型，基础设施层实现 OpenAI/DeepSeek 适配器，Axum 只承接鉴权、流式响应与任务状态。前端通过独立 hooks 消费，不将 API key 发送到浏览器。

### Agent 核心扩展边界

- `domain::agent` 定义任务、所需能力与任务输入输出，不依赖 Axum、编辑器或某一家模型 SDK。当前已实现任务能力校验；运行实例与适配器接口在接入首个模型调用时增加。
- 模型适配器按协议分开：OpenAI 兼容文本/图像接口与即梦接口分别编码请求、解析结果及错误。模型 ID 完全由后台配置，不假定用户给出的 `image2.5` 或其他别名一定可用。
- 工具注册表使用稳定工具名、JSON Schema 参数、权限和超时；网络搜索、网盘搜索以受控服务端适配器实现。模型只提出调用，核心验证参数和权限后执行，并把结果作为数据回传模型。密钥不进入提示词或工具返回值。
- Skill 是版本化的指令与工具需求清单；安装时校验来源、记录版本、由管理员启用，不执行任意下载脚本。MCP 连接单独管理传输、工具枚举、参数校验和访问范围，不让模型自行注册或启动服务。
- 对话、写作、摘要、配图复用任务路由与运行记录；每次运行记录模型、工具调用、错误和耗时。长任务支持取消，生成结果先进入草稿或素材库，再由管理员确认发布。

写作与摘要任务已开放运行接口。图像任务使用后台绑定的图像模型，通过兼容 `images/generations` 的 HTTPS API 生成；即梦配置应填火山方舟兼容地址和支持该协议的模型 ID。服务端接受 base64 或公开 HTTPS 签名图片地址，限制响应及图片大小、校验图片头和尺寸，下载地址拒绝内网 IP 与重定向。生成结果先保存为私有 OSS 素材，管理员在编辑器里采用后公开，主图绑定素材 UUID，配图插入 Markdown。上传与模型请求失败不修改文章。其他模型协议需单独适配。

## 主图风格模板

参考站的相纸框、16:9 裁切和底部印刷带由 UI 完成，不要求生成模型把相框画进图片。可配置的图片提示模板强调：编辑式拼贴、主题明确的双主体或隐喻、克制双色、半色调印刷纹理、留白、无额外标题文字。管理员可以按文章主题调整；不复用参考站原始插画。

## 评论审核工作流

匿名评论先进入现有 pending 队列。后续 Agent 以评论、文章上下文和站点审核规则为输入，输出结构化 decision/reason/confidence。规则通过、模型高置信且管理员启用自动通过时，工作流调用审核服务；不确定或失败时保持待审核。任务需有幂等键、重试状态、决策记录与人工覆盖入口，模型文本本身不能直接执行发布或删除动作。

## 实施顺序

1. AI 提供商配置、服务端凭据和连接测试。
2. 续写/改写与发布摘要，再接入具备真实 FIM 能力的模型。
3. 图片生成任务、素材入库、主图选择，以及 Mermaid 预览。
4. 评论审核 Agent、运行记录与管理员可控的自动通过规则。

## 评论审核 Agent

后台「Agent → 模型」为「评论自动审核」绑定文本模型即可开启，选择「关闭自动审核」停止领取新任务；已开始的调用可能完成。新评论以数据库 pending 记录作为持久队列，单条处理并使用 Redis 短租约防止重复调用。

模型仅接收文章标题、昵称、评论正文和有限父评论上下文，不接收邮箱摘要、文章全文或服务端密钥，不授予 Skill、搜索、抓取工具。正常讨论及批评通过，明确广告诈骗、辱骂威胁、隐私泄露拒绝；不确定、调用失败或无效输出交给人工。后台评论页展示理由，允许人工覆盖、隐藏、删除或重新提交审核。失败不自动反复重试。

人工处理或重提递增 review_version，模型以条件更新写回；状态、版本、审核时间或结果已改变时丢弃过期结果。模型输出先严格校验枚举与理由长度，不直接执行任何正文指令。开启后会处理尚未经人工处理的存量待审评论。

验证：`cargo test --workspace`；独立已迁移的临时 PostgreSQL 可执行 `OXIDE_MANAGEMENT_TEST_DATABASE_URL=... cargo test stale_agent_cannot_override_manual_or_resubmitted_review -- --ignored`，测试强制要求库名 oxide_management_test，防止使用生产库。
